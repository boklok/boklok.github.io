<!--more-->

![Day 2 배너](/assets/images/invitation-service-day2-banner.png)

어제 글에서 "일단 되긴 되는" 서비스를 만들었다면, 오늘은 "믿고 써도 되는" 서비스로 바꾸는 하루였어요. 겉모습은 크게 안 바뀌었는데, 속은 많이 달라졌습니다.

**실제 서비스**: [https://invitation-service-nine.vercel.app](https://invitation-service-nine.vercel.app)

## 1. "너가 알아서 끝까지 해봐"

오늘은 실험 삼아 AI한테 이렇게 말해봤어요. "네가 알아서 모든 걸 끝까지 진행해도 돼. 대신 내가 반드시 정해야 하는 것만 알림으로 알려줘."

그랬더니 AI가 먼저 스스로 판단해서 목록을 쭉 뽑아왔어요. "이건 내가 알아서 할 수 있는 일이고, 이건 사장님(?)이 직접 결정해야 하는 일이에요" 하고 나누더라고요. 예를 들면:

- **AI가 알아서 처리한 것**: 개인정보 동의 문구 넣기, 스팸 방지, 초대장 삭제 기능, 테스트 코드 작성, 모바일 화면 깨짐 고치기, 검색엔진 노출 설정
- **저한테 물어본 것**: "카카오 지도를 실제로 붙이려면 사장님 명의로 API 키를 발급받아야 해요", "결제 기능은 사업 관련 결정이라 사장님이 정해야 해요"

이 구분이 꽤 마음에 들었어요. 잡다한 건 알아서 처리하고, 진짜 제가 결정해야 할 것만 콕 집어서 물어보니까요.

*(스크린샷 자리: AI가 "이건 직접 결정해주세요"라고 목록 뽑아준 대화 화면)*

## 2. 개인정보는 함부로 받으면 안 되니까

하객이 참석 여부를 남길 때 이름·연락처를 입력받는데, 이게 "개인정보"라서 그냥 막 받으면 안 되더라고요. 그래서:

- "이 정보를 왜 모으는지, 얼마나 보관하는지" 안내 문구를 추가하고
- 동의 체크박스를 필수로 넣었어요 (체크 안 하면 제출 자체가 안 되게)
- 방명록처럼 애초에 공개 목적인 글은 굳이 동의 절차를 따로 안 뒀어요 (성격이 다르니까)

그리고 같은 초대장에 누가 계속 스팸처럼 RSVP를 반복 제출하는 것도 막았어요. 10분에 5번 넘게 보내면 자동으로 막히게요.

## 3. 지도, 진짜로 붙였어요 (근데 삽질 좀 했어요)

어제는 "카카오맵 앱으로 연결되는 버튼"만 달았는데, 오늘은 화면에 지도를 진짜로 박아 넣었어요. 근데 이게 생각보다 삽질이 컸어요.

카카오 개발자 센터에서 "지도 기능 쓸게요"라고 키(API 키)를 발급받았는데, 화면에 자꾸 지도가 안 뜨는 거예요. 브라우저 개발자 도구를 열어보니 "이 도메인은 허용 안 함" 같은 에러가 떴어요.

알고 보니 카카오 개발자 센터 안에 **똑같이 생긴 설정 화면이 두 개**가 있었어요. 하나는 "카카오톡으로 링크 공유할 때"를 위한 설정이고, 다른 하나는 "웹페이지에 지도를 직접 넣을 때"를 위한 설정인데, 저는 처음에 엉뚱한 화면에 주소를 등록했던 거였어요. 스크린샷을 몇 장 주고받으면서 "아, 이 화면 말고 저 화면이요!" 하고 찾아낸 다음에야 해결됐어요.

*(스크린샷 자리: 실제 초대장 페이지에 카카오맵이 뜬 화면)*

## 4. 폰트 하나 때문에 서버가 통째로 멈추는 미스터리

이번 삽질이 제일 골치 아팠어요. 테스트를 자동으로 돌리는 도구(Playwright)를 도입했는데, 갑자기 서버가 응답을 아예 안 하는 거예요. 껐다 켜도 또 멈추고.

범인은 다름 아닌 **한글 웹폰트**였어요. 구글 폰트를 인터넷에서 실시간으로 받아오는 방식으로 써놨었는데, 이 환경에서 그 요청이 가끔 먹통이 되면서 서버 전체를 물귀신처럼 끌고 들어가버린 거예요. 겉으로 보면 "테스트가 이유 없이 멈춤"처럼 보이는데, 사실은 폰트 하나가 원인이었던 거죠.

해결은 의외로 심플했어요. 폰트 파일을 아예 미리 다운로드해서 프로젝트 안에 넣어두고, 인터넷에서 매번 받아오지 않도록 바꿨어요. 그랬더니 거짓말처럼 멈추는 일이 없어졌어요.

## 5. 사람이 안 눌러봐도 확인되는 자동 테스트

여태까진 제가 직접 클릭하면서 "어, 되네" 하고 확인했는데, 오늘은 그 과정을 통째로 자동화했어요. 로그인 → 초대장 만들기 → 편집 → 발행 → 하객이 참석여부 남기기 → 방명록 쓰기 → 지도 뜨는지까지, 사람 대신 프로그램이 브라우저를 직접 조작하면서 13가지 시나리오를 매번 자동으로 검사하게 만들었어요.

덕분에 이제 뭔가 고칠 때마다 "혹시 다른 데가 망가지지 않았나" 하나하나 손으로 확인 안 해도, 명령어 하나로 13개가 전부 통과하는지 바로 알 수 있어요.

*(스크린샷 자리: 터미널에 13개 테스트가 전부 초록색 체크로 통과하는 화면)*

## 6. 알림을 디스코드로 받으려다, 결국 텔레그램으로

배포 진행 상황 같은 걸 폰으로 먼저 알림받고 싶어서 "디스코드로 알려줄 수 있어?" 하고 물어봤어요. 근데 디스코드 알림을 받으려면 "웹훅 URL"이라는 걸 새로 만들어야 하는데, 이게 은근 손이 가는 작업이더라고요.

생각해보니 이미 어제 만들어둔 텔레그램 봇이 있었어요. 굳이 새로 뭘 만들 필요 없이 "그거 재사용하면 되지 않아?" 싶어서 그쪽으로 방향을 틀었어요. 결과적으로 훨씬 빠르고 간단하게 끝났어요. 이미 있는 걸 활용하는 게 나을 때도 있더라고요.

*(스크린샷 자리: 텔레그램으로 "배포 완료" 알림 받은 화면)*

## 7. 수익모델, 일단은 가볍게

"이 서비스로 돈은 어떻게 벌까?" 하는 질문에 AI가 세 가지 선택지를 줬어요.

1. 그냥 무료로 계속 운영
2. 결제 기능 없이, 마음 있는 사람만 개인 송금으로 후원
3. 진짜 결제 시스템(PG) 붙여서 유료 템플릿 판매

사업자 등록도 안 한 상태라 3번은 시기상조였고, 그렇다고 아예 손 놓고 있기도 아쉬워서 **2번**으로 골랐어요. 그리고 카카오페이·토스 중에 뭘로 할지 물어보길래 **토스**로 정했어요.

카카오톡으로 갖고 있던 토스 QR코드 사진을 하나 던져줬더니, AI가 그 이미지 안의 QR코드를 읽어서(사진 속 QR을 코드로 직접 해석하는 도구를 설치해서) 실제 송금 링크를 뽑아내고, 그걸로 "후원하기" 페이지를 뚝딱 만들어줬어요. QR 이미지 하나, 버튼 하나, "안 하셔도 전혀 상관없어요"라는 문구까지요.

*(스크린샷 자리: /support 후원 페이지 실제 화면)*

## 오늘 하루 요약

- 개인정보 동의 + 스팸 방지 + 초대장 삭제 기능
- 카카오맵 실제 임베드 (도메인 설정 삽질 포함)
- 한글 폰트를 자체 호스팅으로 바꿔서 서버 먹통 버그 해결
- 자동 테스트 13개 도입 (로그인부터 방명록까지 전 과정)
- 텔레그램 봇 알림 재사용
- 토스 송금 기반 가벼운 후원 페이지 오픈

이렇게 이틀에 걸쳐서 "일단 되는" 서비스에서 "믿고 아무나 써도 되는" 서비스로 넘어왔어요. 어제가 뼈대를 세우는 날이었다면, 오늘은 그 뼈대에 안전벨트를 채우는 날이었던 것 같아요.

다음엔 사업자 등록하고 나면 진짜 결제 시스템도 한 번 붙여볼까 생각 중이에요.
