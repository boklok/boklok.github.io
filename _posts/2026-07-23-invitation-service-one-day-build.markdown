AI 코딩 도구랑 같이 하루 만에 모바일 청첩장 서비스를 기획부터 배포까지 만들어본 기록이에요.

<!--more-->

![이음 서비스 흐름도](/assets/images/invitation-service-banner.png)

## 어쩌다 시작했냐면

"돌잔치·청첩장 초대장 서비스 하나 만들어볼까?" 하는 생각에서 시작했어요. 아워스페이퍼(ourspaper.com) 같은, 예쁜 템플릿 고르고 내용만 채우면 링크 하나로 짜잔 발행되는 그런 서비스요. 오늘 하루 동안 AI 코딩 도구(Claude Code)랑 같이 기획부터 실제 배포까지 다 해봤는데, 생각보다 재밌어서 기록으로 남겨요.

> 참고로 저는 개발자가 아니고, "이런 서비스 만들고 싶다"는 아이디어만 던지고 AI한테 하나씩 물어보면서 진행했어요. 그래서 이 글도 최대한 처음 보시는 분들이 이해할 수 있게 썼습니다.

**실제로 돌아가는 서비스**: [https://invitation-service-nine.vercel.app](https://invitation-service-nine.vercel.app) (지금 바로 들어가서 초대장 만들어보실 수 있어요!)

## 1. 뭘 만들지부터 정했어요

처음엔 "청첩장만 만들자"고 생각했는데, 곰곰이 생각해보니 청첩장·돌잔치·환갑잔치·집들이가 사실 구조가 다 비슷하더라고요. 어차피 다 "언제·어디서 하는지 + 사진 몇 장 + 참석 여부 물어보기 + 계좌번호 + 축하 메시지" 조합이니까요.

그래서 **"공통으로 쓰는 부분"** (표지, 인사말, 일시·장소, 사진첩, 참석여부 묻기, 계좌번호, 방명록, 공유하기) 이랑, **"행사마다 다른 부분"** (청첩장이면 신랑신부 소개, 돌잔치면 아기 성장앨범)을 나눠서 설계했어요. 이렇게 하니까 하나만 잘 만들어두면 5가지 행사 종류를 다 커버할 수 있었어요.

## 2. 어떤 도구로 만들지 정하기

**Next.js**(웹사이트를 만드는 도구)랑 **Supabase**(회원가입·로그인·데이터 저장·사진 저장을 한 번에 해결해주는 서비스)를 조합해서 쓰기로 했어요. 쉽게 말하면 "집(Next.js)"과 "집에 필요한 전기·수도·창고(Supabase)"를 따로 준비 안 하고 세트로 가져다 쓴 느낌이에요.

시작부터 재밌었던 게, 제 컴퓨터에 Node.js(웹사이트를 만들 때 필요한 기본 프로그램)조차 안 깔려있어서 그것부터 설치했어요. 그리고 프로젝트를 막 만들었더니 "이건 네가 아는 그 Next.js가 아니다, 코드 짜기 전에 문서부터 읽어라"는 경고 파일이 자동으로 딸려왔어요. 최근에 나온 새 버전이라 AI가 학습한 정보랑 실제 사용법이 좀 달랐던 거예요. 그래서 작업하는 내내 공식 문서를 직접 찾아 읽어가면서 진행했답니다.

*(스크린샷 자리: 터미널에서 `npm run dev` 실행하고 `localhost:3000` 첫 화면 띄운 모습)*

## 3. 로그인은 비밀번호 없이, 이메일 링크로

요즘 서비스들 보면 비밀번호 없이 "이메일로 링크 보내드릴게요, 클릭하면 로그인돼요" 하는 방식 많이 보셨죠? 그거로 했어요. 비밀번호 까먹을 걱정도 없고, 만들기도 상대적으로 간단해서요.

*(스크린샷 자리: 로그인 화면 + 실제로 받은 매직링크 이메일)*

## 4. 초대장 만들기 → 편집 → 발행

이벤트 종류 고르고(청첩장/돌잔치/...) → 템플릿 고르고 → 편집 화면에서 내용 채우고 → "임시저장" 또는 "발행하기" 누르는 흐름을 만들었어요.

여기서 은근 까다로웠던 게 **사진 업로드 버튼**이었어요. 원래 "저장하기" 버튼 하나로 모든 내용을 한 번에 저장하게 만들었는데, 사진 업로드는 별도로 즉시 처리돼야 하거든요. 근데 웹페이지 만드는 규칙상 "버튼 묶음(폼)" 안에 또 다른 "버튼 묶음"을 못 넣어요. 이런 규칙이 있는 줄도 몰랐는데, 덕분에 하나 배웠어요. (결국 `form="다른폼이름"`이라는 속성으로 "겉보기엔 안에 있지만 실제로는 다른 곳에 있는 폼"을 참조하게 만들어서 해결했어요.)

*(스크린샷 자리: 편집 화면 전체 — 사진 업로드하고 미리보기 뜬 상태)*

## 5. 하객들도 로그인 없이 참석여부·축하글 남길 수 있게

초대장 받는 사람 입장에선 회원가입하고 로그인하고 그러면 너무 귀찮잖아요. 그래서 **하객은 로그인 없이** 참석 여부 남기고, 방명록에 축하 메시지 남길 수 있게 만들었어요.

근데 여기서 재밌는 포인트: "참석 여부"는 호스트(초대장 만든 사람)만 볼 수 있어야 하고, "방명록"은 다른 하객들도 다 볼 수 있어야 하잖아요. 이런 "누가 뭘 볼 수 있는지" 규칙을 데이터베이스 자체에 설정해뒀어요. 서버 코드가 따로 막는 게 아니라, 데이터가 저장되는 곳(Supabase)에 "이 데이터는 이런 사람만 볼 수 있음"이라고 미리 정해두는 방식이에요. 훨씬 안전하더라고요.

*(스크린샷 자리: 실제 초대장 링크로 들어가서 RSVP 남기는 화면 + 방명록 화면)*

## 6. 템플릿 4종 실제로 다르게 만들기

처음엔 "심플/플로럴/모던/파스텔" 이름만 있고 다 똑같이 생겼었는데, 진짜로 다르게 보이도록 만들었어요.

- **심플**: 하얀 배경에 깔끔한 기본 글씨체
- **플로럴**: 은은한 로즈핑크 배경 + 우아한 한글 명조체
- **모던**: 흑백 고대비 + 굵직한 느낌의 글씨체
- **파스텔**: 보라-하늘-노랑 그러데이션 배경 + 동글동글 귀여운 글씨체

*(스크린샷 자리: 4개 템플릿을 나란히 캡처해서 붙인 비교 이미지)*

## 7. 카카오톡 공유하면 미리보기 카드 뜨게

만든 초대장 링크를 카카오톡으로 보내면, 그냥 파란 글씨 링크만 뜨는 게 아니라 사진이랑 제목이 예쁘게 카드 형태로 뜨게 만들었어요. (다들 카톡으로 링크 보낼 때 사진 크게 뜨는 카드 보신 적 있으실 거예요, 그거예요.)

그리고 "오시는길" 버튼도 만들었는데, 지도를 화면에 직접 박아넣는 대신 **카카오맵·네이버맵 앱으로 바로 연결되는 버튼**만 달았어요. 지도를 직접 붙이려면 복잡한 절차(전용 열쇠 발급, 주소를 좌표로 바꾸는 작업 등)가 더 필요한데, 버튼만으로도 충분히 쓸만하더라고요.

*(스크린샷 자리: 카카오톡으로 링크 공유했을 때 뜨는 미리보기 카드)*

## 8. 배포하다가 만난 미스터리

가장 재밌었던(?) 삽질은 배포할 때 벌어졌어요. 서비스를 실제 인터넷에 올리는 걸 "배포"라고 하는데, Vercel이라는 곳에 배포를 시켰더니 몇 분이 지나도 상태가 계속 "알 수 없음"으로 멈춰있는 거예요.

처음엔 그냥 느린 줄 알고 취소했는데, 알고 보니 정상적으로 진행되던 걸 제가 성급하게 취소해버린 거였어요 (교훈: 좀 기다려볼 걸). 다시 해봐도 또 멈추길래 자세히 들여다보니 이유가 나왔어요 — "커밋(코드 저장 기록)을 남긴 사람이 진짜 이 계정 주인인지 확인이 안 됨". 제 컴퓨터가 코드 기록을 남길 때 진짜 이메일이 아니라 "boklok@맥북이름.local" 같은 가짜 이메일을 자동으로 쓰고 있었더라고요. GitHub 계정에 등록된 진짜 이메일로 설정을 바꾸고 나서야 배포가 뚫렸어요.

*(스크린샷 자리: Vercel 대시보드에서 배포 성공(READY) 뜬 화면)*

## 9. 덤으로, 텔레그램으로 원격 확인까지

마지막으로 재미삼아 텔레그램 봇을 하나 만들었어요. 폰으로 봇한테 "상태"라고 보내면 최근 배포 상태랑 사이트가 잘 돌아가는지 확인해서 답해주고, "배포"라고 보내면 다시 배포까지 해줘요. 대신 "이거 고쳐줘" 같은 자유로운 지시는 못 하게 막아뒀어요 — 코드를 읽을 수만 있고 고칠 수는 없는 안전 모드로만 답하도록요. 컴퓨터를 껐다 켜도, 봇이 죽어도 자동으로 다시 켜지게 설정도 해뒀고요.

*(스크린샷 자리: 텔레그램에서 봇이랑 대화한 화면)*

## 마무리하며

하루 만에 아이디어 → 로그인 → 초대장 만들기 → 사진 업로드 → 실제 디자인 → 배포까지 다 되는 게 신기했어요. 그리고 느낀 건, AI랑 같이 만들어도 결국 "왜 이게 안 되지?"를 파고드는 건 여전히 사람 몫이라는 거예요. AI가 코드 짜는 속도는 확실히 빠르게 해주지만, 문제가 터졌을 때 원인을 찾아서 판단하는 과정은 똑같이 필요하더라고요.

다음엔 지도를 화면에 직접 붙이거나, 알림 기능 같은 걸 더 추가해볼까 생각 중이에요.
