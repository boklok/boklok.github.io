어제 [텔레그램 AI 비서 봇]({% post_url 2026-07-23-personal-ai-telegram-assistant %})을 만든 얘기를 올렸었는데, 오늘은 거기에 살을 좀 더 붙였어요. 개발 방식이 재밌었는데, "더 발전시킬 방법이 뭐가 있을까?"라고 Claude Code한테 먼저 물어보고, 나온 제안 중에 끌리는 걸 그대로 "다 추가해줘"라고 시켰어요. 그렇게 하루 만에 기능 5개가 늘었습니다.

## 1. 조용히 죽어있어도 몰랐던 문제 — 워치독

지금까지 만든 자동화들은 다 `launchd`(맥의 자동 실행 스케줄러)로 돌아가는데, 생각해보니 이 중 하나가 에러로 죽어버려도 저는 알 방법이 없더라고요. 알림을 보내야 할 스크립트 자체가 고장났으니, 당연히 "고장났다"는 알림도 안 오는 거죠.

그래서 1시간마다 다른 작업들의 상태를 확인하는 감시자 스크립트를 하나 추가했어요. `launchctl list` 명령으로 각 작업의 "마지막 종료 코드"를 확인할 수 있는데, 이게 0이 아니면 실패했다는 뜻이에요. 실패를 감지하면 바로 텔레그램으로 알려주고, 같은 실패를 계속 반복해서 알리지 않도록 상태를 기록해뒀어요.

## 2. 죽은 링크를 계속 감시하고 있었다는 걸 알았어요

가격 감시 목록에 등록해둔 상품 중에 품절되거나 페이지 구조가 바뀌면, 가격을 추출하는 정규식이 더는 못 찾는 경우가 생겨요. 근데 지금까지는 그냥 조용히 "이번엔 못 찾았네" 하고 넘어가고 있었더라고요 — 몇 주째 죽은 링크를 붙잡고 있어도 알 방법이 없었던 거죠.

이제 3번 연속으로 가격을 못 찾으면 "이거 정리하시는 게 어때요?"라고 알림을 보내도록 바꿨어요. 다시 가격을 찾으면 카운터가 리셋되니까, 일시적인 접속 오류 정도로는 오작동하지 않아요.

## 3. "그거 얼마였지?" 못 알아듣던 봇에 기억력 달아주기

원래 봇은 메시지 하나하나를 완전히 독립적으로 처리했어요. 방금 뭘 물어봤든 다음 질문에서는 깡그리 잊어버리는 거죠. Claude Code CLI에 `--session-id`랑 `--resume`이라는 옵션이 있길래, 대화 세션 ID를 파일에 저장해뒀다가 다음 질문에서 이어서 물어보도록 바꿨어요.

여기서 살짝 조심한 부분이, `-c`(가장 최근 대화 이어가기) 옵션을 그냥 쓰면 안 됐다는 거예요. 이 봇도 저와 같은 폴더에서 `claude` 명령으로 돌아가다 보니, 자칫하면 제가 코드 작업할 때 나눈 대화랑 봇이 사용자와 나눈 대화가 뒤섞일 뻔했어요. 그래서 봇 전용 세션 ID를 따로 발급해서 완전히 분리했어요. "대화 초기화"라고 말하면 언제든 리셋도 가능하고요.

## 4. 알림이 얼마나 오는지 통계 내기

브리핑, 가격 알림, 일정 리마인더, 특가 알림… 종류가 늘어나다 보니 "이거 실제로 얼마나 유용한가?"가 궁금해졌어요. 텔레그램 API로는 사용자가 알림을 진짜 읽었는지까지는 알 수 없어서, 일단 "얼마나 자주 보냈는지"만 한곳에 기록해두는 로그를 만들었어요. "알림 통계"라고 물어보면 최근 7일간 어떤 알림이 몇 번 왔는지 정리해서 답해줘요. 나중에 너무 잦다 싶은 알림을 줄이는 판단 근거로 쓸 생각이에요.

## 5. 음성 메시지로 말 걸기 — 그리고 오늘의 삽질

마지막은 제일 재밌었던 부분이에요. 텔레그램으로 음성 메시지를 보내면 알아듣게 만드는 건데, 여기서부터는 이 맥북(메모리 16GB)의 제약을 감안해서 로컬 STT(음성인식) 모델을 쓰기로 했어요. Apple Silicon에 최적화된 MLX 포맷의 Whisper 모델이면 가볍게 돌아가니까요.

**삽질 1 — 모델 이름이 틀렸어요.** `mlx-community/whisper-base`라는 이름으로 다운로드를 시도했는데 401 에러가 났어요. "인증이 필요한가?" 싶어서 한참 헤맸는데, 알고 보니 그냥 리포지토리 이름 자체가 틀렸던 거였어요. 실제 이름은 `whisper-base-mlx`(뒤에 `-mlx`가 붙어요). 이름 하나 잘못 쓴 걸 권한 문제로 착각해서 삽질한 케이스였어요.

**삽질 2 — 숨어있던 의존성.** 텔레그램 음성 메시지는 OGG/Opus라는 형식으로 오는데, 이걸 디코딩하려면 `ffmpeg`이라는 별도 프로그램이 필요했어요. 처음엔 이게 없어서 조용히 실패했는데, 원인을 찾고 나서 `brew install ffmpeg`으로 간단히 해결했어요.

**테스트는 어떻게 했냐면**, 진짜 음성 메시지를 보낼 수도 있었지만, 그냥 맥의 `say` 명령어(텍스트를 소리 내어 읽어주는 기능)로 한국어 음성 파일을 만들어서 그걸 인식시켜봤어요. "오늘 날씨 어때요? 가격 감시 목록 보여줘"라고 만든 파일을 넣었더니, "오늘 날씨 어때요? 가격 잠시 묵로 보여줘"라고 살짝 틀리게 인식하더라고요. 작은 모델(140MB 정도)이라 완벽하진 않지만, 대충 무슨 말인지는 파악할 수 있는 수준이라 개인 비서 용도로는 충분해 보였어요.

인식된 텍스트는 기존에 만들어둔 라우팅 로직(URL이면 가격 등록, "워치리스트"면 목록 조회, 그 외엔 Claude에게 질문)을 그대로 재사용하도록 만들어서, 텍스트로 치나 말로 하나 똑같이 동작해요.

## 마무리하며

오늘 느낀 건, "더 발전시킬 방법 추천해줘 → 다 추가해줘" 이 패턴이 생각보다 잘 먹힌다는 거였어요. 대신 다섯 가지를 한 번에 밀어붙이다 보니, 하나씩 검증하면서 진행하는 게 중요하더라고요. 실제로 모델 이름 오타, 빠진 의존성(ffmpeg), 세션이 다른 대화랑 섞일 뻔한 위험 같은 게 중간에 계속 나왔는데, 그때그때 실제로 돌려보면서 잡아냈어요. AI가 코드를 빨리 짜주는 건 맞는데, "진짜 되는지"는 결국 실행해보고 확인하는 수밖에 없더라고요.
