[하루 만에 뼈대를 세우고]({% post_url 2026-07-23-invitation-service-one-day-build %}), [다음 날 안전벨트를 채운]({% post_url 2026-07-24-invitation-service-production-ready %}) 모바일 청첩장 서비스 [이음](https://myeum.kr)이, 그 뒤로 열흘 정도 사이에 꽤 많이 달라졌어요. 한 번에 정리해두려고 이 글을 씁니다.

<!--more-->

**실제 서비스**: [https://myeum.kr](https://myeum.kr) (정식 도메인도 이번에 연결했어요)

## 1. 디자인을 통째로 갈아엎었어요

처음엔 그냥 무난한 화이트/그레이 톤이었는데, "고급스러운 청첩장 느낌이 안 난다" 싶어서 Google의 AI 디자인 도구([Stitch](https://stitch.withgoogle.com))로 무드보드를 여러 개 뽑아봤어요. 그중 마음에 든 "네이비 + 샴페인 골드" 조합을 골라서 사이트 전체 색상·폰트·여백 체계를 다시 짰습니다.

템플릿도 5종(심플/플로럴/모던/파스텔/럭셔리) 전부 실사 이미지를 새로 입혔어요. 처음엔 제가 몇 개 만들다가, 나머지는 Stitch로 직접 이미지를 뽑아서 넘겨받아 적용하는 식으로 나눠서 진행했습니다. 템플릿 선택 카드가 밋밋한 텍스트 버튼에서 실제 사진이 배경으로 깔린 카드로 바뀌니 확실히 느낌이 달라지더라고요.

## 2. "선택하기 버튼 눌러도 반응이 없어요"

배포하고 며칠 지나서 이런 피드백을 받았어요. 코드를 까보니 버튼 자체는 멀쩡히 동작하고 있었는데, 누르는 순간 아무 시각적 반응이 없다 보니 "안 눌리나?" 하고 여러 번 연타해서 임시 초대장이 중복으로 쌓이고 있었던 거예요. 실제로 대시보드에 테스트용으로 만든 초대장이 여러 개 쌓여 있는 걸 보고서야 원인을 확실히 알았어요.

이 버그 하나를 고치다가, "그러고 보니 다른 버튼들도 다 이런 식이잖아?" 싶어서 나중에 사이트 전체로 로딩 표시를 넓히게 됩니다. (7번에서 이어집니다.)

## 3. 경쟁사 하나 뜯어보고, 나온 아이디어를 몽땅 적용했어요

"바른손카드"라는 실제 모바일 청첩장 서비스에 로그인해서 AI한테 자유롭게 돌아다니며 참고할 만한 기능을 모아오라고 시켜봤어요. 다녀와서 정리해온 아이디어 중에 "이거 다 적용해줘, 나한테는 최소한만 물어봐도 돼"라고 통째로 맡겼습니다. 그렇게 붙은 기능이 꽤 많아요:

- **RSVP 항목 커스터마이징** — 신랑측/신부측 구분, 식사 여부, 동행인 성함, 전세버스 탑승 여부를 호스트가 켜고 끌 수 있게
- **계좌 여러 개 + 카카오페이 송금 링크** — 원래 고정 2칸이던 걸 무제한 추가/삭제로 바꾸고, 계좌번호 대신 카카오페이 링크도 걸 수 있게
- **캘린더 & D-day** — 결혼일이 하이라이트된 월간 달력과 실시간 카운트다운
- **신랑신부 이름 순서 선택** + 커버 전용 이름(영문/애칭) 표기
- **섹션 드래그로 순서 바꾸기**
- **오프닝 애니메이션 + 낙화 파티클 효과**(꽃잎/눈)
- **현장 스냅** — 하객이 행사 당일 사진을 로그인 없이 올릴 수 있는 기능
- **전자화환(축하 선물)** — 하객이 카드로 소액 결제해서 축하를 전하는 기능

이 중 전자화환이 좀 까다로웠어요. 결제하는 사람이 로그인 안 한 익명 하객이다 보니, 기존에 있던 "호스트 전용 결제"랑 완전히 다른 보안 패턴이 필요했거든요. 결제 상태를 바꾸는 권한 자체를 아예 안 열어두고, 토스 결제 승인 API로 서버가 직접 검증한 다음에야 관리자 권한으로만 "결제완료" 상태로 바꾸도록 만들었어요. 그래야 누가 결제 안 하고 상태만 조작하는 걸 막을 수 있으니까요.

## 4. 작업 중간에 끼어든 요청들도 같이 처리했어요

기능을 한창 붙이던 중에 세 가지가 더 들어왔어요.

- **이미 만든 초대장에도 나중에 섹션 추가하기** — 원래는 처음 만들 때 고른 종류(청첩장/돌잔치 등)에 따라 섹션이 고정이었는데, 나중에라도 "RSVP 섹션 하나 더 붙이고 싶다" 하면 편집기에서 바로 추가할 수 있게 됐어요.
- **임시저장 일괄 삭제** — 테스트하면서 쌓인 임시 초대장들을 체크박스로 여러 개 골라서 한 번에 지울 수 있게.
- **클릭하면 처리 중이라는 걸 보여주기** — 2번에서 발견한 문제를 사이트 전체로 확장했어요. 저장/발행/로그인/RSVP 제출/삭제 등 폼 제출 버튼 전부에 눌렀을 때 즉시 비활성화되고 "처리하는 중..." 같은 문구가 뜨도록 통일했습니다.

## 5. 정식 도메인도 연결했어요

`invitation-service-nine.vercel.app`이라는 기본 주소 대신 `myeum.kr`이라는 정식 도메인을 붙였어요. 파비콘·앱 아이콘도 새로 만들어 넣었고, 그동안 꺼두었던 구글 로그인도 정식으로 활성화했습니다. 소셜 로그인 버튼(구글/카카오/네이버)에는 각 브랜드 로고도 넣어서 좀 더 신뢰가 가도록 다듬었어요.

## 6. 실사용해보고 나온 자잘한 불편들

운영 중인 서비스를 직접 써보면서 나온 피드백을 모아서 한 번에 처리했어요.

- **일시 입력 연도가 6자리로 들어가는 버그** — 날짜 입력창에 연도 자리 제한이 따로 없어서, 계속 숫자를 입력하면 "202607" 같은 이상한 값이 그대로 저장될 수 있었어요. 입력 가능한 연도 범위를 정해서 막았습니다.
- **연락처 자동 하이픈** — 신랑/신부 연락처, 하객 연락처 입력할 때 010-1234-5678처럼 자동으로 하이픈이 붙도록.
- **초대장 주소를 직접 정하기** — 처음엔 `myeum.kr/i/ff1c05d905`처럼 난수 주소로만 발행됐는데, 원하는 문자열로 바꿀 수 있게 했어요.
- **럭셔리·플로럴 템플릿에 입체감 주기** — 단색 배경이 밋밋하다는 얘기가 나와서, 새 이미지를 추가하는 대신 그러데이션과 그러데이션 텍스트만으로 깊이감을 더했어요.
- **발행 전 미리보기** — 임시저장 상태에서도 호스트 본인만 실제 템플릿 그대로 미리 볼 수 있는 페이지를 새로 만들었어요.

## 7. 다 갈아엎고 나니, 안 쓰는 코드도 나오더라고요

이것저것 계속 고치고 붙이다 보니 "이거 아직도 쓰나?" 싶은 코드가 궁금해져서 한 번 훑어봤어요. 확인해보니 초기에 프로젝트 템플릿 그대로 남아있던 브라우저용 Supabase 클라이언트 파일(실제로는 서버 쪽에서만 접근하는 구조라 필요 없었던 것)이랑, 만들어놓고 한 번도 안 쓴 아이콘 컴포넌트 2개를 찾아서 정리했습니다.

## 오늘까지 요약

- 네이비+골드 디자인 전면 개편, 5개 템플릿 실사 이미지 적용
- 경쟁사 벤치마킹 기반 기능 8종 (RSVP 커스터마이징, 카카오페이, 캘린더, 이름 순서, 섹션 순서 변경, 오프닝 애니메이션, 현장 스냅, 전자화환)
- 섹션 나중에 추가하기, 임시저장 일괄 삭제, 전체 로딩 상태 표시
- 정식 도메인(myeum.kr) 연결, 구글 로그인 활성화
- 날짜/연락처 입력 개선, 커스텀 주소, 템플릿 비주얼 보정, 발행 전 미리보기
- 안 쓰는 코드 정리

하루짜리 실험으로 시작한 서비스가 열흘 사이에 실제로 누가 써도 될 만큼 이것저것 채워졌어요. 다음엔 사업자 등록 마무리되면 정식 결제 시스템(PG)도 붙여볼 생각입니다.
